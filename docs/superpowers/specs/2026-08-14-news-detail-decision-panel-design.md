# 新闻详情页审批决策区设计

## 目标

拥有当前新闻发布审核资格的用户，在新闻提交详情页右侧不仅能看到审核流程，也能直接完成自己的审核决定。详情页与列表式审核台必须使用同一套决策规则和交互，避免权限与按钮状态漂移。

## 已确认方案

采用共享决策面板。审核台和详情页复用同一个 `ContentReviewDecisionPanel`，而不是在详情页复制审批逻辑或仅提供跳转链接。

详情页右栏顺序为：

1. 审核流程
2. 我的抉择
3. 发布后可见范围
4. 返回入口

## 服务端授权契约

详情查询负责返回浏览器可安全消费的决策状态，但服务端 mutation 仍是最终授权边界。

- `canDecide` 仅在提交状态为 `pending`、当前阶段为 `publication_approval`、当前账号拥有该类别的 `canManage` 权限，并且当前账号的审核任务仍可处理时为 `true`。
- 当前账号已有待处理任务时返回其 `myTaskId`。
- 当前账号拥有管理权限但旧提交尚无任务时，允许沿用现有 mutation 的服务端惰性建任务能力；浏览器仍只提交 submission ID、可选 task ID、决定和意见。
- 来源审阅阶段不在详情页处理，继续使用新闻来源审阅台。
- 创建者、历史任务参与者或超级管理员可以按既有规则查看详情，但查看权不自动等于决策权。
- 权限被撤销、任务已跳过、其他审核人已经完成或提交不再待审时，`canDecide` 必须为 `false`。

## 共享组件

`ContentReviewDecisionPanel` 接收：

- submission ID
- 可选 task ID
- `canDecide`
- 提交与任务状态
- 成功后的回调

待处理时显示审核意见输入框、“不通过”和“同意”。不通过必须填写意见；同意时意见可选。提交期间禁用重复操作。

不能处理时不显示失效按钮，而显示准确原因：

- 已由其他审核人处理
- 当前账号仅可查看流程
- 该提交已完成审核
- 来源审阅需前往来源审阅台

详情页成功处理后由响应式查询刷新审核流程和决策状态；审核台继续显示原有成功消息。

## 错误处理

- 客户端展示服务端返回的安全业务错误。
- 缺少意见、重复决定、任务过期或权限撤销均不得静默失败。
- 详情查询继续对不存在、类别不符和不可访问的提交统一返回 `null`，不泄露资源是否存在。

## 测试

- 服务端：有 `canManage` 且任务待处理时 `canDecide=true`；仅有查看关系、来源审阅权、已处理任务、已完成提交或权限撤销时均为 `false`。
- 组件：详情页渲染“我的抉择”；同意可无意见，不通过缺少意见会阻止提交；忙碌状态阻止重复提交；只读状态显示原因。
- 回归：审核台仍能审批；创建者仍能查看流程但不能决策；来源审阅仍只能在来源审阅台处理。
- 浏览器：使用真实本地提交打开详情页，验证右侧决策区、完成一次决定并确认流程即时更新。

## 非目标

- 不改变新闻来源审阅流程。
- 不扩大新闻权限范围。
- 不修改内容发布后的管理能力。
