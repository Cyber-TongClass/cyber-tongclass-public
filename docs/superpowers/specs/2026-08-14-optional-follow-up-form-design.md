# 后续表单“必须完成 / 仅开放”设计

## 目标

“填写新表单”流程节点增加两种明确语义：

- 必须完成：抵达节点后授予目标表单权限，原提交停在该节点；申请人成功提交目标表单后，原流程继续。
- 仅开放权限：抵达节点后授予目标表单权限，原流程立即继续，不要求申请人提交。

新建节点默认“必须完成”。既有没有该配置的流程节点保持“仅开放权限”，避免升级改变正在运行的流程。

## 数据与执行

节点新增 `completionRequired?: boolean`。授权记录保存该快照，并可记录满足要求的目标提交 ID 与时间。服务端只信任提交快照和授权记录；目标表单提交成功后，按 `formId + userId` 查询未完成的必填授权，核对原提交仍停在同一节点与同一工作流版本，随后幂等标记完成、写入节点完成事件，并从下一节点恢复。

一个目标提交可以满足同一用户、同一目标表单的多个有效授权；重复提交或重试不会重复推进。目标表单自身的审批结果不影响“已填写”的判定，成功提交即算完成。

## 界面

工作流编辑器在目标表单选择器下提供“必须完成后推进 / 仅开放权限并继续”选择。节点摘要、流程模拟和申请详情都显示这一语义；必填节点抵达但未提交时显示“等待填写”，仅授权节点显示“已开放”。

## 验证

测试覆盖默认与兼容规范化、编辑器控件、服务端阻塞与恢复标记、授权幂等，以及现有工作流回归。只在本地 Bold Sandpiper 验证，不部署 Silverfish。
